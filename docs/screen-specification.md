# イベント参加者調整App MVP画面仕様書

作成日: 2026-06-01

## 1. 位置づけ

本書はMVPで実装する画面、画面遷移、表示項目、操作、入力チェック、エラー表示を定義する。

関連文書:

- `docs/mvp-requirements.md`
- `docs/system-design.md`

## 2. 画面設計方針

### 2.1 共通

- 招待者画面はスマホ優先で設計する。
- 管理画面はPC利用を主想定とし、一覧確認、集計確認、詳細確認を効率よく行える設計にする。
- 管理画面はスマホでも崩れることなく閲覧、操作できるようにする。
- UIはサークル向けのカジュアルアプリではなく、運営者が出欠状況を効率よく確認、集計するためのビジネスアプリ寄りにする。
- 削除操作は原則として物理削除せず、内部的には無効化として扱う。
- マイプランでは画面上の操作名を「削除」とし、確認ダイアログで招待URLからアクセスできなくなることを明示する。
- 保存中、保存成功、保存失敗を画面上で判別できるようにする。
- 入力エラーは対象項目の近くに表示する。
- 操作不可の理由は、可能な限りボタン付近または対象行に表示する。

### 2.2 文言方針

- 画面上では、イベント管理者向けの領域を「管理画面」と表記する。
- 要件定義上の役割名は「イベント管理者」を使用する。
- 招待者向けには、システム用語を避け、短い案内文にする。
- PINは「4桁のPIN」と表記する。
- アクセスコードは「アクセスコード」と表記し、ログインパスワードと混同しない。
- アクセスコード入力欄の近くに `6〜12桁の数字` を表示する。

### 2.3 ビジュアル方針

- 全体のデザインは白、グレーをベースにする。
- アクセントカラーは1色だけ使用する。
- アクセントカラーは主要アクション、選択状態、重要な状態表示に限定して使う。
- 派手な装飾、SNS風、ゲーム風、ポップすぎる表現は避ける。
- 丸み、影、装飾は控えめにし、情報密度と視認性を優先する。
- 管理画面では装飾的なカード多用を避け、テーブル、バッジ、必要最小限のサマリーカードで構成する。
- 招待者画面では読みやすさとタップしやすさを優先し、1カラムで迷わない操作順にする。

## 4. 画面遷移

### 4.1 イベント管理者

```mermaid
flowchart TD
  login["A-01 ログイン"] --> plans["A-03 マイプラン"]
  login --> reset["A-02 パスワードリセット"]
  reset --> login
  plans --> newPlan["A-04 プラン追加"]
  newPlan --> plans
  plans --> planDetail["A-05 プラン詳細・イベント一覧"]
  plans --> planEdit["A-06 プラン編集"]
  planEdit --> plans
  planDetail --> newEvent["A-07 イベント追加"]
  newEvent --> planDetail
  planDetail --> eventDetail["A-08 イベント詳細・出欠内訳"]
  planDetail --> eventEdit["A-09 イベント編集"]
  eventEdit --> planDetail
  eventDetail --> addResponse["A-10 回答代理追加"]
  eventDetail --> editResponse["A-11 回答修正"]
  eventDetail --> pinReset["A-12 PINリセット"]
```

### 4.2 招待者

```mermaid
flowchart TD
  invite["G-01 招待URLアクセス"] --> password{"アクセスコードあり"}
  password -->|あり| passInput["G-02 アクセスコード入力"]
  password -->|なし| entry["G-03 ニックネーム/PIN入力"]
  passInput --> entry
  entry --> responses["G-04 出欠入力"]
  responses --> complete["G-05 出欠入力完了"]
  invite --> error["G-06 エラー"]
  passInput --> error
  entry --> error
  responses --> error
```

## 8. A-03 マイプラン

### 8.1 目的

イベント管理者が自分のプランを一覧し、新規プラン作成や既存プラン管理へ進む。

### 8.2 表示項目

- ページタイトル: `マイプラン`
- プラン数: `x / 3`
- プラン追加ボタン
- 通知有効化状態
- マイプラン

マイプランの表示項目:

| 項目 | 内容 |
| --- | --- |
| プラン名 | プラン名 |
| 年月 | `YYYY年MM月` |
| イベント数 | 有効イベント数 |
| アクセスコード | 設定済み / 未設定 |
| 配信用URL | コピー操作 |
| 作成日時 | 表示 |
| 操作 | イベント、編集、削除 |

表示方針:

- PCではテーブル表示を基本とする。
- 件数はサマリーカードまたはバッジで表示する。
- 行単位の主要操作は右端に集約する。
- スマホでは列数を減らしたカード風の行表示または横スクロールで破綻を防ぐ。
- 削除済みプランは一覧に表示しない。

### 8.3 操作

| 操作 | 結果 |
| --- | --- |
| プラン追加 | プラン追加画面へ遷移 |
| イベント | プラン詳細・イベント一覧へ遷移 |
| 編集 | プラン編集画面へ遷移 |
| URLコピー | クリップボードへコピーし、成功時はボタン付近に `コピーしました` を短時間表示 |
| 削除 | 確認後、画面上から削除し、内部的にはプランを無効化 |
| 通知を有効にする | ブラウザ通知許可を要求し、許可済みならFCM tokenを登録 |

### 8.4 状態別表示

| 状態 | 表示 |
| --- | --- |
| プラン3件 | プラン追加ボタンを無効化し、`プランは最大3件までです。` を表示 |
| プラン0件 | 空状態メッセージとプラン追加ボタンを表示 |
| 削除済みプラン | 一覧に表示しない |

## 10. A-05 プラン詳細・イベント一覧

### 10.1 目的

プラン情報とイベント一覧を確認し、イベント作成、編集、出欠確認へ進む。

### 10.2 表示項目

- プラン名
- 年月
- 状態
- アクセスコード設定有無
- 配信用URL
- コピーボタン
- イベント追加ボタン
- イベント一覧

イベント一覧の表示項目:

| 項目 | 内容 |
| --- | --- |
| イベント名 | 未入力時は `イベント名未設定` |
| 日程 | `YYYY/MM/DD` |
| 時間帯 | AM / PM |
| 場所 | 場所 |
| ステータス | `受付中` / `締切済` の2択セグメント |
| 出欠サマリー | `○ x / △ x / × x` |
| 操作 | 出欠内訳、編集、削除 |

表示方針:

- PCではテーブル表示を基本とする。
- `イベント` 列を一番左に表示する。
- 出欠サマリーの `○`、`△`、`×` 人数は、テーブル内のバッジまたは一覧上部の小さなサマリーカードで一目で分かるようにする。
- ステータスは `受付中` / `締切済` の2択セグメントで表示し、現在値を強調する。
- ステータス変更時は、変更後の影響を確認ダイアログで表示する。
- スマホでは日程、場所、ステータス、出欠サマリー、主要操作が折り返しても読み取れるようにする。

### 10.3 並び順

```text
日程昇順 -> 時間帯順(AM, PM) -> 登録順
```

### 10.4 操作

| 操作 | 結果 |
| --- | --- |
| URLコピー | 配信用URLをコピーし、成功時はボタン付近に `コピーしました` を短時間表示 |
| イベント追加 | イベント追加画面へ遷移 |
| 出欠内訳 | イベント詳細・出欠内訳へ遷移 |
| 受付中 | 確認後、イベントステータスを受付中へ変更し、状態ボタン付近に `変更しました` を短時間表示 |
| 締切済 | 確認後、イベントステータスを締切済へ変更し、状態ボタン付近に `変更しました` を短時間表示 |
| 削除 | 確認後、画面上から削除し、内部的にはイベントを無効化 |

## 11. A-06 プラン編集

### 11.1 目的

プラン名、年月、アクセスコードを変更する。

### 11.2 入力項目

| 項目 | 必須 | 内容 |
| --- | --- | --- |
| プラン名 | 必須 | 現在値を初期表示 |
| 年月 | 必須 | 現在値を初期表示 |
| 現在の設定 | 表示のみ | `アクセスコードあり` / `アクセスコードなし` を表示 |
| アクセスコード操作 | 任意 | 現在設定に応じたラジオボタンを表示 |
| アクセスコード | 条件付き必須 | 設定または変更を選択した場合のみ入力。6〜12桁の数字 |

現在の設定がアクセスコードありの場合:

- `現在のアクセスコードを維持する`
- `アクセスコードを解除する`
- `別のアクセスコードを設定する`

現在の設定がアクセスコードなしの場合:

- `アクセスコードを設定しない`
- `アクセスコードを設定する`

### 11.3 操作

| 操作 | 結果 |
| --- | --- |
| 保存 | プランを更新し、マイプランへ戻る |
| キャンセル | マイプランへ戻る |

### 11.4 注意表示

アクセスコードを変更または解除する場合、以下を表示する。

```text
アクセスコードの変更は招待者へ自動通知されません。必要に応じてLINE等で連絡してください。
```

## 13. A-08 イベント詳細・出欠内訳

### 13.1 目的

イベント単位で出欠サマリーと回答内訳を確認し、管理者代理操作を行う。

### 13.2 表示項目

イベント情報:

- プラン
- 日程
- 時間帯
- 場所
- 状態

イベント情報エリアでは、上記5項目をPC幅で1行に並べて表示する。

出欠サマリー:

| 表示 | 内容 |
| --- | --- |
| ○ | 参加人数 |
| △ | 未定人数 |
| × | 不参加人数 |

回答一覧:

| 項目 | 内容 |
| --- | --- |
| ニックネーム | 表示用ニックネーム |
| 出欠 | ○ / △ / × |
| コメント | 自由入力コメント |
| 回答日時 | 最終回答日時 |
| 最終更新者 | 管理者(Admin) / 招待者(Guest) |
| 操作 | 修正、PINリセット |

PINは表示しない。

表示方針:

- PCでは出欠内訳をテーブル表示する。
- `○`、`△`、`×` の人数は画面上部に小さなサマリーカードまたはバッジで表示する。
- 出欠内訳パネル右上に `代理回答` ボタンを表示する。
- 回答一覧ではニックネーム、出欠、コメント、回答日時、最終更新者を横並びで比較しやすくする。
- コメントが長い場合は行の高さを過度に広げず、省略表示と詳細確認を検討する。
- スマホでは1回答ごとに情報を縦積みし、修正、PINリセット操作が誤タップされない余白を確保する。

### 13.3 操作

| 操作 | 結果 |
| --- | --- |
| 回答代理追加 | 回答代理追加モーダルを開く |
| 回答修正 | 回答修正モーダルを開く |
| PINリセット | PINリセットモーダルを開く |

### 13.4 空状態

回答が0件の場合:

```text
まだ回答はありません。
```

## 18. A-13 通知有効化案内

### 18.1 目的

### 18.2 表示タイミング

- ブラウザ側で自動表示が抑制された場合、または後から許可したい場合は、マイプランの通知ボタンから再実行できる。
- すでに通知許可済みの場合もボタンは表示し、`通知有効` として状態を表示する。

### 18.3 表示文言

ボタン:

```text
通知を有効にする

通知有効
通知拒否中
通知未設定
通知非対応
```

| 通知拒否中 | 押下不可。ブラウザまたは端末設定変更が必要 |
| 通知未設定 | 押下不可。VAPIDキー設定が必要 |
| 通知非対応 | 押下不可 |

### 18.5 状態別表示

| 状態 | 表示 |
| --- | --- |
| 許可済み | 通知設定済み |
| 拒否済み | ブラウザまたは端末設定から通知を許可してください。 |

## 22. G-04 出欠入力

### 22.1 目的

招待者がプラン内のイベントごとに出欠を入力、再編集する。

### 22.2 表示項目

- プラン名
- ニックネーム
- イベント一覧
- 保存ボタン

イベントごとの表示項目:

| 項目 | 内容 |
| --- | --- |
| 日程 | `YYYY/MM/DD` |
| 時間帯 | AM / PM |
| イベント名 | 未入力時は省略または `イベント名未設定` |
| 場所 | 場所 |
| ステータス | 受付中 / 締切済 |
| 出欠 | ○ / △ / × |
| コメント | 自由入力 |

表示方針:

- 招待者側はスマホ優先の1カラムUIにする。
- イベントごとに日程、時間帯、場所、ステータス、出欠選択、コメントを上から順に表示する。
- 受付中イベントは表示する。
- 締切済イベントは、招待者本人の既存回答がある場合のみ表示する。
- 締切済かつ未回答のイベントは表示しない。
- 出欠選択は `〇`、`△`、`×` のSVGアイコンのみを大きめのボタンで横並びに表示する。画面上の文字ラベルは表示しないが、アクセシビリティ用のラベルは保持する。
- 選択中の出欠はアクセントカラーで明確に示す。
- 未選択、締切済、保存中の状態が視覚的に判別できるようにする。

### 22.3 イベント状態別UI

| 状態 | UI |
| --- | --- |
| 受付中、未回答 | 出欠選択とコメント入力を有効 |
| 受付中、回答済 | 既存回答を初期表示し、編集可能 |
| 締切済、未回答 | 表示しない |
| 締切済、回答済 | 既存回答を表示し、編集不可 |
| 無効化済み | 表示しない |

### 22.4 操作

| 操作 | 結果 |
| --- | --- |
| 保存 | 回答を保存し、完了画面へ遷移 |
| 戻る | ニックネーム/PIN入力へ戻る |

### 22.5 保存時エラー

| 条件 | 表示 |
| --- | --- |
| 保存直前にプラン無効化 | このプランは現在利用できません。 |
| 保存直前にイベント締切 | 一部のイベントが締切済になったため保存できませんでした。内容を確認してください。 |
| 通信失敗 | 保存に失敗しました。時間をおいて再度お試しください。 |

## 25. レスポンシブ仕様

### 25.1 招待者画面

スマホ:

- 1カラム
- イベントごとに縦積みカード表示
- 出欠選択は横並びの大きめボタン
- 保存ボタンは画面下部またはフォーム末尾に明確に配置

PC:

- 中央寄せの狭めコンテナ
- スマホと同じ操作順を維持

### 25.2 管理画面

PC:

- マイプラン、イベント一覧、出欠内訳はテーブル形式を基本とする。
- 出欠内訳は横幅を活かして表示する。
- `○`、`△`、`×` の人数はカードまたはバッジで一目で分かるように表示する。
- 主要操作ボタンは画面上部と対象行に配置する。

スマホ:

- 表は列数を減らしたカード風の行表示または横スクロールで破綻しないようにする。
- マイプラン、イベント一覧、出欠内訳の閲覧と主要操作がスマホでも成立するようにする。
- 削除、PINリセットなどの重要操作は誤タップを避けるため確認を必須にする。

## 26. テスト観点

画面テストは、ケース作成前に以下の観点を列挙してから詳細化する。

### 26.1 機能観点

- ログイン、ログアウト、パスワードリセット
- プラン作成、編集、削除
- アクセスコード設定、変更、解除
- URLコピー
- イベント作成、編集、削除
- イベントステータス変更
- 招待者初回入力、再編集
- 管理者代理追加、回答修正
- PINリセット
- 通知許可UI
- FCM token登録
- Service Worker登録
- PWA manifest

### 26.2 非機能観点

- スマホ幅での入力しやすさ
- PC幅での一覧視認性
- 低速回線での保存中表示
- 通知非対応ブラウザ
- 通知拒否済みブラウザ
- PWAインストール可否
- Service Worker更新時のキャッシュ影響
- ネットワーク切断時のエラー表示

### 26.3 データ観点

- PIN先頭0
- 同一ニックネーム同一PIN
- 同一ニックネーム別PIN
- 長いニックネーム
- 長いコメント
- イベント名未入力
- 無効化済みプラン
- 締切済イベント

### 26.4 状態遷移観点

- 初回回答から完了画面へ遷移する。
- 再編集時に既存回答が復元される。
- 受付中から締切済に変更後、招待者画面で編集不可になる。
- PINリセット後、旧PINで入れず新PINで入れる。
- 初回自動要求が完了しなかった後、管理画面から再度有効化できる。
- 通知タップ後、対象プランのイベント一覧へ遷移する。
