## 確認観点

ケース作成に先立ち、以下の観点を定義した。

- 機能: 認証、プラン/イベントCRUD、出欠、代理対応、URL共有、LINE登録/配信、Push、PWA。
- 非機能: 所有者による分離、ネットワーク依存、キャッシュ、端末/ブラウザ差、並行要求、部分失敗。
- データ: コレクション、入力上限、コード/PIN、固定イベント集合、無効化、既存セッション、監査/配信ログ。
- UI: 実在する画面・遷移、URL例、コピー、送信結果、ヘルプ/PDFと現行操作の一致。
- 正常系: 初回回答/再編集、手動LINE配信、プラン・イベント編集。
- 異常系: 不正コード、権限不一致、締切・削除、通信/外部API/ログ保存失敗。
- 境界値: プラン3件、ニックネーム40文字、コメント/挨拶文500文字、友だちメモ120文字、イベント100件、LINE宛先50件。
- 状態遷移: 共有後の締切・削除、PIN/アクセスコード変更、通知許可/拒否、LINEブロック/再登録、部分失敗後の再送。

## 実装上の制約・未保証事項

文書の修正で以下の実装が改善されたわけではない。設計上の期待と、現行実装の保証範囲を分ける。

| 優先度 | 項目 | 現行実装・影響 | 根拠 |
| --- | --- | --- | --- |
| 重大 | PIN/アクセスコード変更時の既存Cookie | 新たな照合は新しい値を要求するが、既存Cookieを即時失効させるバージョン照合がない。セッションは24時間継続できる。 | [session.ts](../src/lib/invite/session.ts)、[回答API](../src/app/api/i/[inviteCode]/responses/route.ts) |
| 重大 | 同時要求の状態・上限保証 | プラン数やニックネーム既存登録の確認と作成、イベント状態確認と回答batch commitは単一トランザクションではない。並行作成・保存中の締切変更に対する厳密な保証は未検証。 | [プラン作成API](../src/app/api/admin/plans/route.ts)、[server.ts](../src/lib/invite/server.ts) |
| 重大 | 照合要求のレート制限 | PIN/アクセスコード/招待コード照合に回数制限・ロックを行うアプリ内実装がない。レート制限は将来の改善候補であり実装済みとは記載しない。 | [entry API](../src/app/api/i/[inviteCode]/entry/route.ts)、[password API](../src/app/api/i/[inviteCode]/password/route.ts)、[codeLookup.ts](../src/lib/invite/codeLookup.ts) |
| 重大 | LINE配信の重複・部分失敗 | 宛先別の結果は返すが要求の重複排除/自動再送がない。通信失敗時の再操作や全件再送は成功済み宛先にも届きうる。 | [LINE配信API](../src/app/api/admin/line/messages/route.ts) |
| 軽微 | Webhook再送・処理失敗 | 決定的friendIdで登録の重複は抑止する。イベント単位の重複排除はなく、個別処理失敗をログに残して200を返す。自動回復を保証しない。 | [Webhook](../src/app/api/line/webhook/[lineAccountId]/route.ts)、[friends.ts](../src/lib/line/friends.ts) |
| 軽微 | 複数公式アカウント | データはlineAccountIdを持つが、資格情報は共通の1組。アカウントごとの資格情報切り替えはない。 | [config.ts](../src/lib/line/config.ts) |
| 軽微 | イベント無効化の監査 | 要件には記録対象として存在するが、Firestore直接更新処理は監査ログを書かない。記録済みとして扱わない。 | [events/data.ts](../src/features/admin/events/data.ts) |
| 軽微 | PWAのオフライン範囲 | 画面/静的資産のキャッシュはあるが、保存/LINE配信のキューや同期はない。ローカルではService Workerを解除する。 | [Service Worker](../public/sw.js)、[登録処理](../src/features/pwa/serviceWorker.ts) |

これらは機能追加や再現試験の結果として扱わない。特に競合はソースから確認した非原子的処理であり、発生頻度・本番再現性は未検証。
まず防ぐべき問題は、変更済み認証情報での既存セッション継続、状態変更との競合、意図しない重複配信である。
